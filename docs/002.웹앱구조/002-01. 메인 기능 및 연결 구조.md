# 푸드덕(Fooduck) 주요 기능 구조와 연결 관계

대상 주소: `http://localhost:8081/` (메인/홈 페이지)

## 전체 구조

Spring Boot 단일 앱. 백엔드(`springboot/src/main/java/.../backend/`, 도메인별 패키지)와
프론트엔드(정적 HTML/JS, `springboot/src/main/resources/static/`)가 한 프로젝트에 통합되어 있음.
별도 SPA 프레임워크 없이 바닐라 JS + 정적 리소스로 동작.

- 백엔드 도메인 패키지: `auth`, `board`, `map`, `preset`, `recommendation`, `restaurant`, `review`, `favorite`, `mypage`, `admin`, `business`, `news` 등
- 프론트엔드: `index.html`(홈), `pages/<기능>/index.html`(각 기능 페이지), `js/api.js`(공통 fetch 래퍼), `js/common.js`(공통 헤더/푸터/세션/아이콘)
- 라우팅: 정적 파일은 경로 그대로 서빙(`/pages/...`), API는 전부 `/api/**`에 `@RestController`로 매핑
- 인증: `SecurityConfig`가 JWT 기반 Stateless 인증, URL별 접근권한을 화이트리스트로 관리
- `springboot/ai/`에 Python 추천 스크립트(`app.py`, `recommend.py` 등)가 존재하지만, 현재 `/api/recommendations`는 이를 호출하지 않고 Java(`RecommendationPreviewService`)에서 DB 집계로 점수를 계산 중. AI 연동은 준비만 되어 있고 실제 흐름에는 아직 연결되지 않음
- DB 마이그레이션: `springboot/src/main/resources/db/migration/V1~V10__*.sql`

## 5개 주요 기능과 API

| 기능 | 페이지 | JS/CSS | 호출 API |
|---|---|---|---|
| 통합 검색 | `/pages/search/index.html` | `search.js`, `search.css` | `GET /api/public/map/restaurants/search` |
| 지도에서 찾기 | `/pages/map/index.html` | `map.js`, `map.css` | `/api/public/map/config`, `/api/public/map/restaurants`, `/restaurants/search`, `/api/presets/{id}/map-restaurants`, `POST/DELETE /api/restaurants/{id}/favorite` |
| 맞춤 추천 | `/pages/recommendation/index.html` | `recommendation.js` | `GET /api/recommendations` (인증 필수, 미로그인 시 401 → 로그인 리다이렉트) |
| 커뮤니티 게시판 | `/pages/board/index.html` | `board-shared.js`, `board.js` | `/api/board/posts`, `/best`, `/popular`, `/best/community`, `/unanswered`, `/business-access` |
| 인기 Presset | `/pages/presset/index.html` | `presset.js` | `GET /api/presets`, `/tags`, `POST /api/presets`(등록), `POST/DELETE /api/presets/{id}/favorite` |

공통으로 모든 페이지가 `/js/api.js` → `/js/common.js` → 페이지 전용 JS 순으로 로드됨.

## 기능 간 연결 흐름

### 홈 → Presset → 지도 (연쇄 연동)
홈의 "지금 인기 있는 맛집 모음" 섹션은 `home.js`가 `GET /api/presets?page=0&size=4&sort=popular`를 호출해 카드 4개를 렌더링. 각 카드는 `/pages/presset/detail.html?presetId=…`로 연결됨. Presset 상세 페이지의 "지도 보기" 버튼은 `/pages/map/index.html?presetId=…`로 이동하고, `map.js`가 URL의 `presetId`를 감지해 일반 검색 대신 `GET /api/presets/{presetId}/map-restaurants`를 호출해 해당 프리셋 맛집만 지도에 표시. `presetId` 쿼리 파라미터로 홈 → Presset → 지도가 하나의 흐름으로 연결됨.

### 검색 → 지도
검색 결과 카드의 "지도에서 보기" 링크는 검색어(`q`)를 그대로 들고 `/pages/map/index.html?q=<검색어>`로 이동. 검색과 지도 모두 동일한 백엔드 엔드포인트(`/api/public/map/restaurants/search`)를 사용해 데이터 소스가 동일함.

### 로그인 상태 → 맞춤 추천
`common.js`의 `readSession()`이 `localStorage`의 JWT(`accessToken`)를 디코드해 로그인 여부를 판단. 헤더 내비게이션의 "맛집추천" 링크(`data-recommendation-link`)는 로그인 여부에 따라 `/pages/recommendation/index.html` 또는 `/pages/auth/login.html?next=...`로 동적으로 변경됨. 페이지 진입 시 `recommendation.js`가 다시 세션을 확인해 미인증이면 즉시 로그인 페이지로 리다이렉트. 백엔드도 `/api/recommendations`가 화이트리스트에 없어 JWT 없이는 401 반환. 추천 결과 카드는 다시 맛집 상세나 지도 페이지(위경도 쿼리 포함)로 연결되어 순환됨.

### 찜(즐겨찾기) 공유
`map.js`, `presset/detail.js`, `restaurant/detail.js`가 모두 동일한 `POST/DELETE /api/restaurants/{id}/favorite` 엔드포인트를 사용. 어느 화면에서 찜을 하든 같은 `favorite` 테이블에 반영되고, 마이페이지와 추천 점수 계산(`RecommendationPreviewService.personalScore`의 `favoriteByUser` 가중치)에도 영향을 줌.

### 커뮤니티는 독립적
board 쪽은 presset/map/recommendation과 API를 공유하는 직접적 데이터 연동이 없고, 홈의 "커뮤니티" 카드에서 단순 라우팅 링크만 제공.

## 공통 컴포넌트와 인증/세션 처리

- **site-header/footer**: 모든 페이지 HTML에는 `<div data-site-header data-active-nav="...">`, `<div data-site-footer>` placeholder만 있고, `common.js`가 로드 시 `renderHeader`/`renderFooter` 함수로 실제 마크업을 주입. 로그인 여부(`session.authenticated`)와 권한(`ROLE_BUSINESS`, `ROLE_ADMIN`)에 따라 메뉴 구성이 동적으로 결정됨.
- **아이콘 시스템**: Material Symbols 텍스트를 `common.js`의 `ICON_PATHS` 딕셔너리로 인라인 SVG로 치환하는 자체 구현(`enhanceIcons`, `MutationObserver`로 동적 요소도 처리).
- **인증/세션**: 서버 세션이 아닌 **JWT + localStorage** 방식.
  - `Api`(`js/api.js`)가 모든 요청에 `Authorization: Bearer <accessToken>` 헤더를 자동 첨부, 401 발생 시 `/api/auth/refresh`(쿠키 기반 리프레시 토큰)로 액세스 토큰 갱신 후 원요청 1회 재시도.
  - `common.js`의 `readSession()`이 JWT payload(`sub`, `loginId`, `authorities`)를 직접 디코드해 만료 여부를 클라이언트에서 판단, 만료 시 즉시 `localStorage.removeItem`.
  - 백엔드는 `JwtAuthenticationFilter` + `JwtProvider`가 `Authorization` 헤더를 검증해 SecurityContext를 채우고, `SecurityConfig`가 URL 패턴별 인가 규칙(공개 GET, 인증 필요, ROLE_ADMIN/ROLE_BUSINESS 전용)을 선언적으로 관리.
- **빠른 이동 위젯**: `common.js`의 `renderQuickRemote()`가 홈/마이페이지/검색 진입 시 플로팅 네비게이션(`quick-remote`)을 추가로 렌더링.
